# github-router

A Cloudflare Worker that routes short URLs to public GitHub assets owned by
`chewygumxx`. `gh.cgxx.dev` redirects to GitHub's web interface;
`raw.gh.cgxx.dev` streams file contents under the requested hostname.

## Current state

As of 2026-11-08, the two-host implementation is complete and locally
validated. The readiness work is on `improve/worker-readiness`, based on
`main` at `c9c9ed8`. Check the current branch and worktree before resuming;
the branch may have been integrated since this note was written.

The recorded baseline is 18 Bun tests and 36 workerd integration tests,
strict Worker/tooling typechecks, a fresh frozen install, and a successful
Wrangler deployment dry run. Both local development modes were smoke-tested.
No Cloudflare deployment or live-domain acceptance results have been recorded
for this work. Authentication, the intended account, existing remote Worker
state, Custom Domain provisioning, and live GitHub responses still need to
be checked during deployment.

The next milestone is **deploy the existing implementation and record live
acceptance**, following [Deployment and live acceptance](#deployment-and-live-acceptance).
Release downloads, API routing, private repositories, and cache-policy changes
are later features, not prerequisites for that milestone.

## URL contract

```text
https://[raw.]gh.cgxx.dev[/<repo>[@ref][/filepath]]
```

| URL | Result |
| --- | --- |
| `https://gh.cgxx.dev/` | Redirect to the owner's GitHub profile |
| `https://gh.cgxx.dev/github-router` | Redirect to the repository homepage |
| `https://gh.cgxx.dev/github-router@main` | Browse the repository at `main` |
| `https://gh.cgxx.dev/github-router/README.md` | Browse the file using `HEAD` |
| `https://gh.cgxx.dev/github-router@main/README.md` | Browse the file at `main` |
| `https://gh.cgxx.dev/github-router@main/src/` | Browse a directory at `main` |
| `https://raw.gh.cgxx.dev/github-router/README.md` | Serve the raw file using `HEAD` |
| `https://raw.gh.cgxx.dev/github-router@main/README.md` | Serve the raw file at `main` |

An omitted reference becomes `HEAD`, addressing the repository's default
branch. Explicit references may be branch names, tags, or commit SHAs.
Paths ending in `/` select GitHub's directory view; other nonempty paths
select its file view. The router does not query GitHub to identify objects.

A slash in a reference must be encoded within the first path component:
`/github-router@feature%2Frouter/README.md`. The router preserves that boundary
when constructing GitHub URLs. GitHub's resolution of overlapping branch and
file paths is not guaranteed by this project; simple references and commit
SHAs are the supported starting point.

Web redirects use HTTP 302 and preserve the query string for repository
URLs. The profile redirect does not forward a query string. Raw requests
require a file path, ignore the query string, and preserve upstream status,
content type, and cache headers. Raw responses remove `Set-Cookie` and add
`Access-Control-Allow-Origin: *` and `X-Content-Type-Options: nosniff`.

Both hosts accept `GET` and `HEAD`; other methods return 405 with
`Allow: GET, HEAD`. Malformed selectors and raw requests without a file return
400. Unrecognised hosts return 404; raw upstream fetch failures return 502.
Upstream HTTP errors, such as a missing file's 404, pass through unchanged.
A `*.workers.dev` deployment hostname uses web redirect behavior.

## Development

Use Bun 1.4 and Node.js 24 or later. Bun manages dependencies and scripts;
Node runs Wrangler and the integration-test driver. Production code runs in
Cloudflare's workerd runtime and uses standard Web APIs.

```sh
bun install --frozen-lockfile
bun run dev --local
```

With the configured routes, Wrangler infers the web origin for local
requests. In another terminal:

```sh
curl -I http://localhost:8787/
curl -I http://localhost:8787/github-router@main/README.md
```

For raw mode, stop the web development server and start:

```sh
bun run dev --local --local-upstream raw.gh.cgxx.dev
curl -fsS http://localhost:8787/github-router@main/README.md
```

The raw development command selects the hostname seen by the Worker. Setting
a `Host` header alone does not override Wrangler's inferred origin. Raw local
requests fetch public files from GitHub, so they require network access.

## Validation and types

```sh
bun run types             # Regenerate Worker runtime declarations
bun run types:check       # Check the generated declarations are current
bun run typecheck         # Check Worker source and tooling separately
bun run test:unit         # Fast request tests in Bun
bun run test:integration  # Production bundle tests in workerd, driven by Node
bun run test              # Both suites
bun run check             # Lint, types, both suites, and deployment dry run
```

Commit `bun.lock` and `worker-configuration.d.ts`. Run `bun run types` after
changing Wrangler's compatibility date, flags, bindings, or version. The
Worker's checked JavaScript uses generated Cloudflare types; Bun types are
reserved for tests and tooling. Generated declarations are excluded from
formatting and linting.

Integration tests use the installed Wrangler test harness and intercept
outbound GitHub requests with fixed responses. A separate test-only Worker
fixture rejects fetch inside workerd to test network-error handling, because
Miniflare converts Node mock exceptions into HTTP 500 responses. Tests do not
need GitHub or Cloudflare credentials or live GitHub access. They validate
runtime behavior, not deployed DNS/TLS or all GitHub branch-resolution cases.

## Configuration

`src/config.js` defines the GitHub owner, base domain, and operation
subdomains. `wrangler.jsonc` defines the two Custom Domains. Keep these
hostnames aligned when changing configuration.

The current deployment target is the top-level `github-router` Worker,
compatibility date `2026-11-08`, with `workers_dev: true` and Custom Domains
`gh.cgxx.dev` and `raw.gh.cgxx.dev`. There are no named Wrangler environments,
bindings, required secrets, or configured account ID. Check account selection
rather than assuming that an authenticated account is the intended one.

`buildConfig()` derives hosts at module load. It currently does not validate
GitHub account existence, DNS syntax, or duplicate subdomains. A nullish
subdomain omits that operation's hostname; an empty string uses the base
domain. Configuration changes must also be reflected in Wrangler's domains.

## Deployment and live acceptance

This is the resume procedure; the commands below have not been used to deploy
this work. Run them from the checkout containing the readiness changes.

### 1. Establish the local and remote target

```sh
git status --short --branch
git worktree list
git log -6 --oneline
bun install --frozen-lockfile
bun run check
bunx --no-install wrangler whoami
```

Use `improve/worker-readiness` or the commit into which it was integrated.
Inspect `src/config.js` and `wrangler.jsonc`; verify the account owns the
`cgxx.dev` zone and is the intended deployment account. If authentication is
missing, use `bunx --no-install wrangler login` or the established protected
API-token mechanism. Keep credentials out of Git, reports, and chat.

Inspect existing Worker deployments before replacing anything:

```sh
bunx --no-install wrangler deployments list
bunx --no-install wrangler deployments status
```

An absent Worker may make these commands report that nothing exists. Record
that result; do not treat it as proof that the account or zone is correct.
Inspect current domain bindings and dashboard configuration, and reconcile
any differences with the checked-in configuration before deployment.

### 2. Deploy the verified commit

Once deployment is requested and the target is established:

```sh
git rev-parse HEAD
bun run deploy
```

Record the UTC time, full Git SHA, Wrangler version, Worker/account identity,
version/deployment identifiers, returned workers.dev URL, and Custom Domain
results. Cloudflare provisions DNS and certificates for Custom Domains,
including nested names. See the [Custom Domains documentation](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).

A successful upload is not live acceptance. Allow provisioning to finish,
then verify both HTTPS hostnames. If an existing production deployment needs
recovery, inspect its recorded version and current Wrangler rollback guidance
before acting; this runbook does not prescribe an unverified rollback target.

### 3. Exercise live behavior

Use requests that do not automatically follow redirects when inspecting
`Location` headers:

```sh
curl -sS -D - -o /dev/null https://gh.cgxx.dev/
curl -sS -D - -o /dev/null https://gh.cgxx.dev/github-router
curl -sS -D - -o /dev/null 'https://gh.cgxx.dev/github-router@main/README.md?plain=1'
curl -sS -D - -o /dev/null https://gh.cgxx.dev/github-router@main/src/
curl -sS -D - -o /dev/null https://gh.cgxx.dev/github-router@
curl -sS -D - -o /dev/null https://raw.gh.cgxx.dev/github-router
curl -sS -D - -o /dev/null -X POST https://gh.cgxx.dev/github-router
curl -sS -D - -o /dev/null https://raw.gh.cgxx.dev/github-router/README.md
curl -sSI https://raw.gh.cgxx.dev/github-router/README.md
```

| Case | Expected evidence |
| --- | --- |
| Web root | 302, `Location: https://github.com/chewygumxx` |
| Repository | 302 to `https://github.com/chewygumxx/github-router` |
| Explicit-ref file with query | 302 to GitHub `blob/main/README.md?plain=1` |
| Directory with trailing slash | 302 to GitHub `tree/main/src/` |
| Empty explicit ref | 400 |
| Raw repository without a file | 400 |
| POST | 405 and `Allow: GET, HEAD` |
| Raw GET | Expected bytes, upstream content/cache metadata, CORS and nosniff |
| Raw HEAD | Matching success status/metadata, no response body |
| Known missing raw file | Upstream 404 preserved, rather than 502 |
| Returned workers.dev hostname | Web redirect behavior |

Verify raw bytes against GitHub using the same known public commit SHA on
both requests. Select a commit that GitHub can serve; an unpushed local commit
is not a valid upstream fixture. For example, after setting `public_ref`:

```sh
public_ref=REPLACE_WITH_A_PUBLIC_COMMIT_SHA
evidence_dir=$(mktemp -d)
curl -fsS "https://raw.gh.cgxx.dev/github-router@${public_ref}/README.md" -o "$evidence_dir/proxy.md"
curl -fsS "https://raw.githubusercontent.com/chewygumxx/github-router/${public_ref}/README.md" -o "$evidence_dir/upstream.md"
cmp "$evidence_dir/proxy.md" "$evidence_dir/upstream.md"
```

Also test an omitted ref against GitHub's `HEAD` endpoint. Treat it separately
from the pinned comparison because the default branch can move. Encoded slash
references need a known public branch fixture before claiming GitHub accepts
them end to end. DNS/TLS failures and HTTP mismatches should be recorded with
their actual responses rather than inferred from local tests.

### 4. Leave the next handoff

Create `docs/reports/YYYY-MM-DD-live-acceptance.md` after the run. Include the
deployed Git SHA and deployment identifiers, fixture repository/ref/path,
commands and results, both domains' HTTPS status, header/body observations,
and unresolved failures. Sanitize credentials and sensitive account details.
Distinguish successful local checks, successful deployment, and successful
live acceptance. Update this README's status with a link to the report.

## CI and maintenance

CI runs on pushes to `main`, pull requests, and manual dispatch. The shared
standard workflow performs commit/header/format/metadata checks; the
repository job runs `bun run check`. It does not deploy the Worker. Metadata
sync uses `METADATA_APP_CLIENT_ID` and `METADATA_APP_PRIVATE_KEY`; their remote
configuration has not been verified in this work. They are unrelated to the
Worker's GitHub access and Cloudflare deployment authentication.

Keep the failure fixture's compatibility date/flags aligned with Wrangler
when changing runtime configuration. The shared Biome preset currently emits
an informational schema mismatch (2.5.14 preset, 2.6.6 CLI); checks succeed.
Wrangler's generated declarations contain upstream whitespace warnings, so
preserve generator output rather than hand-formatting it.

## Scope and license

This router accesses public repository files without a GitHub token. Private
repositories, release assets, LFS downloads, API routing, wildcard domains,
and custom edge-cache policies require separate support. Existing upstream
cache headers are retained; the Worker does not add its own cache policy.
